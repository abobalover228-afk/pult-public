# Командная работа в Пульте 2.2

Открой «Общий проект», создай комнату и отправь приглашение участникам.
Создателю нужен `PULT_ROOM_CREATE_TOKEN` в `.env` рядом с исходниками;
остальным достаточно приглашения. Адрес службы знакомства берётся из приложения.

В настройках комнаты укажи репозиторий GitHub. Каждый участник выбирает свою
локальную папку этого репозитория или скачивает его кнопкой «Скачать из GitHub».
Для приватного репозитория Git должен быть авторизован на каждом компьютере.
Токен для PR сохраняется отдельным полем в `.env` (`PULT_GITHUB_TOKEN`);
нужен доступ к выбранному репозиторию и разрешение Pull requests: write.

Кнопки чата и списка задач в верхней строке открывают боковые панели.
Создай карточку вручную или из сообщения команды, отметь свободные задачи
и нажми «Взять в работу». Создатель комнаты подтверждает назначение целиком:
одна задача не может одновременно принадлежать двум участникам.

После подтверждения Пульт скачивает текущую основную ветку и создаёт отдельный
Git worktree и ветку `pult/task-<UUID>` для каждой задачи. Агент запускается
в отдельном личном чате. Каждый участник использует свой аккаунт и свои лимиты.
Если подготовка проекта не удалась, карточка получает ошибку; можно повторить
или освободить её. Папки с незавершённой работой сохраняются.

Агент передаёт результат на проверку, а вопросы и разрешения показываются
статусом «Нужен ответ». Дополнительные задачи агент может вернуть блоком
`pult-tasks` с JSON-массивом объектов `title` и `detail` (до пяти за ответ).
Они автоматически добавляются на доску.

«Изменения и PR» открывает просмотр файлов и diff. После подтверждения
Пульт создаёт коммит, отправляет ветку и создаёт PR. Повторная попытка
использует существующий открытый PR. Если файлы изменились после просмотра,
публикация останавливается. `.env`, ключи и служебные папки исключаются;
публикация останавливается также при обнаружении таких файлов в коммитах задачи.
Это фильтр имён файлов: секреты нельзя вставлять в исходный код.

Объединение PR выполняется на GitHub. После него обнови локальный проект
кнопкой «Обновить проект». Обновление останавливается при незакоммиченных
изменениях. Репозиторий комнаты нельзя менять при наличии назначенных задач.

Создатель комнаты хранит авторитетную доску, остальные — локальную копию.
Пока создатель недоступен, новые назначения не подтверждаются и агенты
не запускаются. Результаты, полученные без связи, сохраняются и отправляются
после восстановления соединения. Приглашение для возврата хранится в `.env`.
Перезапуск службы знакомства удаляет её комнаты из памяти: создай новое
приглашение. История переписки живёт в памяти подключённых участников.

Содержимое идёт через прямой WebRTC-канал. TURN и ретрансляция содержимого
выключены; некоторые NAT и корпоративные сети могут не соединиться.
Проверены три локальных клиента, гонка назначения, передача большой доски,
обмен при выключенной службе знакомства, Git worktrees и локальный push.
GitHub PR проверен через mock API; полноценная проверка между двумя разными
ПК и публикация в реальный GitHub требуют выбранного репозитория и участников.
