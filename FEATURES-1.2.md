# Пульт 1.2 — управление разговором и /fast

## Сворачивание

После завершения хода команды с успешным результатом, изменения файлов, отдельные планы/TODO и рассуждения сворачиваются. Содержимое остаётся в памяти и доступно кликом по строке или через контекстное меню. Основной ответ, ошибки, неотвеченные вопросы и подтверждения не сворачиваются. План — отдельный служебный блок, если провайдер прислал структурированное событие плана. Обычный текст с заголовком «план» внутри основного ответа не вырезается. Старые уже обрезанные провайдером результаты восстановить нельзя; новые результаты Пульта больше не обрезаются до последних 6000 символов.

## Прокрутка

Пока пользователь в конце разговора, Пульт следит за потоком. Прокрутка вверх отключает слежение. «К последним сообщениям · следить» возвращает вниз. Размеры блоков не должны принудительно уводить вниз: используется сохранение позиции по стабильным ID видимых сообщений. В тестовом Preview найдены и исправлены два дефекта: принудительное раскрытие необязательного test-only UserDefaults и вызов scrollTo во время layout. Preview не является устанавливаемым приложением и не входит в дистрибутив.

## Группа GPT

Напиши задачу в поле, нажми **«Группа GPT»**, подтверди дополнительный расход. Главный отдельным запросом делит задачу на **две** подзадачи. Затем идут **два независимых запроса**, после них отдельный запрос сборки общего ответа. Максимум четыре запроса, не рекурсивные агенты. Состояния и результаты каждой задачи раскрываются в панели. Остановка отменяет все активные запросы; поздние ответы игнорируются. При одном сбое главный видит ошибку и результат второго исполнителя. При сбое обоих сборка не запускается.

В Codex используются независимые ephemeral app-server threads, read-only sandbox и отклонение запросов подтверждения. Исполнителям передаётся только аналитическая задача, инструменты и изменения запрещены инструкцией. Папка проекта для них не назначается рабочей. В API используются отдельные Chat Completions requests без tools; ключ берётся из Keychain. Возможность модели вернуть текст зависит от конкретного API.

Это минимальный **аналитический** режим: исполнители не применяют код. Результат можно добавить в основной диалог, который решает дальнейшие действия. Нет параллельной записи в одни файлы. История для анализа текстовая, старые вложения представлены названиями; для анализа самих изображений используй основной чат/Суперпромпт. Claude CLI для этой группы не поддержан: выбери Codex либо API. API-запуск требует отдельного подтверждения в интерфейсе и может стоить денег; реальные платные прогоны при разработке не выполнялись. Fast основного чата не навязывается исполнителям.

## Изменить старое сообщение

Правый клик на пользовательском сообщении → **«Изменить и продолжить отсюда…»**. Можно изменить текст и убрать вложения. Нажатие **«Сохранить старую ветку и продолжить»** является подтверждением исключения старого продолжения. Активную генерацию сначала нужно остановить и дождаться завершения.

Старое продолжение сохраняется отдельной локальной веткой. Новый контекст содержит только предшествующие сообщения и изменённый запрос. Для Codex это новый thread/start с доступной историей; для Claude — новая session-id с историей; для API — новый список messages. Это не имитация provider-native rollback: оригинальная CLI-история остаётся нетронутой. Команды и внешние действия не откатываются и сами по себе повторно не выполняются. История служебных действий передаётся как данные с указанием не повторять их.

Очередь старой ветки приостанавливается и исключается из новой. «Восстановить до правки» возвращает её в текущем сеансе; после перезапуска старую ветку можно открыть в списке разговоров. Очередь, как раньше, хранится только в памяти. Локальные ветки хранятся в `~/Library/Application Support/PultConversations` с правами папки 700 и файлов 600. Восстановленные вопросы/подтверждения — исторические записи, без активных RPC и без повторного выполнения. История и правила имеют стабильные ID. Если старое вложение удалено с диска, провайдер может отклонить его; его можно убрать при правке.

## Общие правила и переопределение чата

Кнопка **«Правила»** открывает общие правила и флажок переопределения. Отключённый флажок — наследование; включённый — текст чата полностью заменяет общие дополнительные правила (в том числе допускается пустая строка). Текущий действующий текст виден ниже. Значения сохраняются в настройках приложения, отдельно от исходников.

Правила применяются со следующего запроса. Codex получает developerInstructions, Claude — --append-system-prompt, API — system message. При изменении правил уже начатого CLI-разговора создаётся отдельный контекст с доступной историей, чтобы не продолжать с устаревшими правилами. Это не изменение обязательных ограничений провайдера и не отмена внешних действий. Очень длинная история может превысить контекст модели: Пульт не выдаёт её за полностью обработанную при ошибке провайдера.

## Закрепления

Правый клик на разговоре → **«Закрепить сверху» / «Открепить»**. Закреплённые показываются отдельной группой сверху. ID Codex — thread UUID, локальной ветки — local:UUID, API — api:UUID. Путь аккаунта и заголовок не используются как ID закрепления. Состояние сохраняется после обновления и перезапуска.

## /fast

- `/fast` — переключить; `/fast on`, `/fast off`, `/fast status`.
- Codex: передаёт serviceTier=fast либо default в последующие запросы.
- Claude: передаёт штатную --settings с fastMode в последующий -p запуск. Доступность зависит от модели, версии CLI и аккаунта.
- Произвольный совместимый API: сообщает, что универсального режима нет; не добавляет неизвестный service_tier и не отправляет slash-команду модели.

Переключение не делает модельных запросов. Индикатор означает **запрошенный** режим, не гарантию ускорения; провайдер может отклонить запрос или применить другой уровень. Fast может увеличивать расход лимитов/денег. Режимы Codex и Claude независимы и действуют в текущем окне.

- https://code.claude.com/docs/en/fast-mode

## Проверки и ограничения

Проверки со stub-транспортами: отдельные запросы группы, частичный сбой, остановка и поздние события; очистка контекста после редактирования и восстановление; сохранение полной строки результата при сворачивании; наследование и перезагрузка правил/закреплений; /fast без модельного вызова и его параметры; расчёт сохранённой позиции. Регрессионные проверки API/Keychain abstraction, Суперпромпта, очереди, вопросов и интеграций CLI.

Визуально: длинный искусственный поток, ручной уход вверх, сохранение видимого текста при поступлении новых строк и кнопка возврата вниз; окно правил. Реальные многоагентные модельные ответы, сетевое применение Fast и все сторонние API не тестировались, платные запросы не запускались. Изображение из черновика требований не использовалось, содержимое не предполагалось.
